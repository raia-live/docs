Braintrust shows you what your agents did. SenseLab is the engine the agent learns from between runs: it decides what to trust, writes and proves its own fixes, and turns the record into a model you own.

---

## What Braintrust does

Braintrust runs one loop. The agent produces traces. Software reads the traces and finds failures. An engineer changes a prompt or the code. The fix ships in the next release.

Braintrust is the observability and evaluation platform for that loop: trace storage, evals, and, since September, an agent that investigates traces and suggests changes for a human to approve.

In that loop the agent is write-only. It produces data and reads nothing back. Learning happens per release, at the speed of a review queue, and what improves is the scaffolding around the agent. The agent itself finishes its thousandth run exactly as capable as its first, and when a rule changes in production it keeps applying the old one, with full confidence, until a person notices.

## What SenseLab does

SenseLab is a self-improvement engine that agents run on. It closes three loops, each one feeding the next.

**Outcomes decide what agents act on.** Before a task, the agent is briefed on what is already known: what has held up, what has been discredited, what started failing this week, and which action has the best record here. After the task, it reports how things ended, and credits that result to the exact knowledge and actions it used. A rule that kept working and then starts failing is flagged as a regime shift. No release, no reviewer, no prompt edit.

**The engine writes its own corrections and proves them.** When a failure keeps recurring, a repair agent drafts the fix on a branch no agent can see, replays it against the runs that failed and the runs that passed, then exposes it to a slice of live traffic against a control. It ships only if it helps without doing harm, and reverts on its own if it regresses. Every proposal, ship and rollback is written back as evidence, so the next draft reads what happened to the last one.

**The record becomes your model.** Every run leaves a sealed trace: what was asked, what the agent read, what it did, how it turned out. That is a labelled training example nobody annotated. Once there are enough, SenseLab trains a small model on your own decisions, scores it against your history, and serves it with the same memory the frontier agent used.

**Agents learn as a fleet.** Every outcome is shared, so a rule change is learned once, by whichever agent meets it first, and every other agent inherits the correction on its next task. A new agent joining a fleet starts from everything the fleet has already validated and is productive on its first task.

## How we are different

| | Braintrust | SenseLab |
| :-- | :-- | :-- |
| **Who uses it** | Engineers, in a dashboard | The agent, in whatever tool it runs in |
| **When learning happens** | Next release | Next run |
| **Who writes the fix** | An engineer | The engine, tested on replay and live traffic before it ships |
| **Who has to act** | A person reviews and ships | Nobody |
| **What a new agent starts with** | Nothing | Everything the fleet has validated |
| **What accumulates** | Logs and eval scores | Outcome-labelled decisions, owned by you |
| **When the model changes** | Start over | The record carries across |
| **End state** | Better prompts | A model trained on your own decisions |

Three differences carry the weight.

- **The loop closes inside the run.** Braintrust improves agents at the speed engineers can review. SenseLab improves them at the speed agents do work, and the more agents you run, the wider that gap gets.
- **The engine fixes itself safely.** Generating a fix is easy; a model does that. Knowing which fixes to trust is the hard part, and it is what separates a self-improving system from one that improves itself into a regression. Braintrust's loop ends in a suggestion queued for a human to judge. SenseLab's ends in a canary against a control, with the evidence written back either way.
- **The record is the asset.** A trace store accumulates logs with a retention window. SenseLab accumulates decisions with outcomes attached, which is the one dataset that cannot be reconstructed later and the one that trains a model. You own it and can export it.

## Where the release loop breaks at scale

The release loop works while one team can read every failure. It stops working at the point most teams are heading toward: many agents, on live operations, under rules that change weekly, on models that change yearly.

- **Rules that change under the agent.** Pricing, policy, an API field, a runbook step. On a trace platform the change shows up as a regression days later; an engineer edits the prompt, the fix ships in the next release, and the prompt is a line longer. With hundreds of rules moving, the review queue is the bottleneck and the prompt is the technical debt. On SenseLab, the first agent to hit the change fails once, the old rule is discredited, and every agent has the new one on its next task.
- **Fleets doing the same job.** Support, on-call, order operations, CI repair. Every agent in a fleet fails in the same places, and on a trace platform each failure is a separate ticket for the same team of reviewers. Trace volume grows with the fleet; reviewer capacity does not. On SenseLab the fleet shares one record, so a lesson is learned once, by whichever agent meets it first.
- **Failures nobody wrote an eval for.** Evals test what was anticipated. A scorer can only judge a case its author foresaw, and production fails on the cases nobody did. SenseLab judges by what happened, so no eval has to exist before the engine can learn from a failure.
- **Fixes that regress something else.** The more fixes a tool proposes, the more a human has to review, and a prompt change that helps one segment and hurts another looks fine in a review queue. SenseLab's engine proposed 32 corrections and shipped 2, because 30 failed replay or canary; a human queue would have had to read all 32.
- **The model swap.** Prompts and harnesses are tuned to a model. When the model changes, the tuning restarts. A SenseLab record survives the swap and lifts the new model on its first task.
- **Cost that never comes down.** On a trace platform you run a frontier model per task indefinitely. On SenseLab the traces become a small model that does the same work at a fraction of the cost, and the memory keeps it current after training.

## Proof

Preregistered benchmarks on GPT-5.5 and Claude Opus 5, with tasks that never repeat and a rule change partway through; the harness and per-episode records are public. The frontier-alone baseline is the agent as it runs on Braintrust: it reads nothing back between runs. The right-hand column is how each scenario plays out on that stack.

| Scenario | SenseLab | On Braintrust |
| :-- | :-- | :-- |
| **A rule changes mid-run** | 45% right first try against 25% for the frontier model alone; unchanged work stays at 100% | The agent runs at the 25% line until the regression shows in a dashboard, an engineer edits the prompt, and the release ships. Every run in between applies the old rule with full confidence. |
| **Tasks handed to a human** | 5%, against 14.9% frontier alone and 8% to 12% for memory stores | The agent has no record of what it does and does not know, so it guesses or escalates. The trace store counts the escalations; the count falls only when a person rewrites the instructions. |
| **The outcome loop itself** | +18 points with the loop on against off; +28 over a hosted memory product | Permanently off. The agent writes traces and reads nothing back, so there is no outcome to credit and nothing to credit it to. |
| **The engine fixes itself** | 32 corrections proposed, 2 shipped, 0 rolled back; the canary caught a draft that would have failed 88% of sessions | Suggestions are queued for approval. The 88% draft passes an offline eval because the eval set does not contain the sessions it breaks, and is found in production. |
| **Ten agents, rule change mid-run** | 37% to 75% right first try, each agent seeing a tenth of the work | Ten agents fail at the same spot and send ten streams of traces to one review queue. One prompt change fixes all ten in the next release; until then each fails on its own. |
| **New agents joining** | 84% of first encounters, against 67% on a memory product and 46% with nothing; a newcomer on a healthy fleet was right on 122 of 122 | A new agent starts at the 46% line. It inherits the prompt and nothing else; whatever the fleet learned in production that nobody has written down yet does not exist for it. |
| **Your own model** | Trained on 200 traces: matched the frontier on house rules, beat it where the rule moved, at one twenty-third the cost per task; its own traces trained a better successor | No training set. The traces carry no outcome label and no record of what the agent relied on. You run a frontier model per task indefinitely, and the prompt tuning restarts with every model swap. |

## What compounds

Three things compound on SenseLab that cannot be started on later.

**The record.** Every task adds a labelled example: what was asked, what the agent read, what it did, how it ended. That label exists only because the engine was in the loop when the task ran. It cannot be scraped, bought or backfilled from a trace store, because trace stores never captured which knowledge the agent acted on or how the task turned out. A team that starts capturing it today is a year behind one that has run on SenseLab for a year, and the gap widens with every agent added. You own the record and can export it — but an export is a snapshot; the only place it keeps learning is inside the engine that credits each new outcome to it.

**The judgement.** Producing a memory or a fix is cheap; a model does it. Deciding what to trust is the product: which entry has held up, which has been discredited, which rule has shifted this week, which draft fix is safe to ship. Those gates are tuned on every failure the engine has seen, and it sees failures a trace platform does not, because it is inside the run. The 30 corrections that failed replay or canary are what make the 2 that shipped trustworthy.

**The model.** Once you have volume, your traces train a model only SenseLab had the data to train, and that model runs with the memory on, so its own traces train the one after it. Anyone can offer you the same frontier model. Nobody else can offer a model trained on your own decisions, or the record that keeps it current. Every model generation inherits the record with no measurable loss, so a better frontier model arrives as an upgrade, not a reset.

Each feeds the others. More agents produce more record; more record sharpens the judgement; both train a better model; the better model runs more tasks. The compounding starts on your first task.

## You do not have to replace Braintrust

SenseLab enters through the agent. Adoption is one MCP entry in a coding agent or three SDK calls, with no instrumentation project, no migration and nothing to run. Observability stays where it is. SenseLab sits on the side of the stack a trace platform does not touch: inside the run, between what the agent did last time and what it does next.

Where it shows up first: teams running many agents on repeated operational work where outcomes are observable and rules change under them — support, on-call, CI repair, deploys, order operations. That is where the same mistake recurs, where a prompt fix decays, and where the per-run loop shows up in the numbers within weeks.

Today an agent's intelligence lives in two places: the weights, frozen at training, and the prompt, written by hand. Everything the agent learns at work is gone when the run ends. Observability vendors are building a better microscope for that loss. SenseLab is the thing that keeps what was learned.
