Sensei is a model for agentic workloads that improves itself. Your agents call it the way they call any model, and Sensei learns from how their work turns out. Each task is recorded as a session, each session gets an outcome, and what worked is carried into the tasks that follow.

Learning is built into Sensei and happens in two ways. On every request, Sensei recalls what earlier work on the project showed and answers with that in hand. As verified successes add up, Sensei also trains a version of itself for the project. [How Sensei learns](/sensei/how-sensei-learns) covers both.

An agent here is any program that calls a model in a loop to get work done: your own code on the OpenAI or Anthropic SDK, a saved agent that decides refund requests, or a coding agent such as Cursor, Claude Code or Codex.

<Note>
Sensei is invite-only for now. An invitation comes with $10 of credit and asks for no card.
</Note>

## Two ways to use it

Your agents can call Sensei as their model. The endpoint speaks the OpenAI and the Anthropic formats, so an agent or tool that can talk to either can talk to Sensei. See [Connect your tool](/sensei/connect-your-tool).

You can also hand Sensei the work itself. This is a run, and Sensei does it on a computer of its own. A run can follow a definition your team saved and call your tools, or change a repository and open a pull request. See [Runs](/sensei/runs/overview).

## What the dashboard holds

The dashboard is at [sensei.sense-lab.ai](https://sensei.sense-lab.ai). Its sidebar has seven sections, and these docs follow the same order.

| Section | What you do there | Docs |
| --- | --- | --- |
| Overview | Read this month's sessions, spend and outcome trend, and see what the learning loop did | [How Sensei learns](/sensei/how-sensei-learns) |
| Sessions | Open any task call by call and say how it went | [Sessions](/sensei/sessions), [Outcomes](/sensei/outcomes) |
| Runs | Start work, answer runs that wait for you, manage saved agents | [Runs](/sensei/runs/overview) |
| Projects | Group keys by kind of work and decide what happens to new versions of your model | [Projects](/sensei/projects), [Your model](/sensei/your-model) |
| Routing | Decide which model answers which call | [Routing](/sensei/routing/overview) |
| Usage & cost | Check the balance and where it went, and add credits | [Usage and cost](/sensei/usage-and-cost) |
| Access management | Create keys, copy the endpoint settings, invite people | [Access](/sensei/access) |

## Plans

Sensei is prepaid. An account holds credits and its calls draw them down.

| | Developer | Team | Enterprise |
| --- | --- | --- | --- |
| Price | Credits as you use them | $200 a month, all of it added as credits | Contract |
| The endpoint, runs, sessions and outcomes | Yes | Yes | Yes |
| A model trained on your project's work | No | Yes | Yes, one for each project |
| Your own provider keys and routing rules | No | Yes | Yes |
| More than one project | No | No | Yes |

Rates are the same on every plan. They are listed on [Usage and cost](/sensei/usage-and-cost).
