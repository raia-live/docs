Sensei runs are available as an MCP server. Add one address to Claude, Cursor or Codex, and you can say "run refund-requests on ticket 48213", "approve it" or "that one was wrong" in chat.

## Add the server

The address is on the dashboard: open **Runs**, click **New run**, then **Run it from Claude, Cursor or code**. It has this form:

```
https://runs.sense-lab.ai/mcp/
```

How you sign in depends on the tool.

| Tool | Sign-in |
| --- | --- |
| Cursor, Codex, Claude Code | Send your Sensei key as the `Authorization` header: `Bearer amfs_...` |
| Claude Desktop, claude.ai | Add the address as a connector and sign in when asked |

In Cursor, add this to `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "sensei-runs": {
      "url": "https://runs.sense-lab.ai/mcp/",
      "headers": { "Authorization": "Bearer amfs_..." }
    }
  }
}
```

## What the chat tool can do

| Tool | Does |
| --- | --- |
| `run_start` | Starts a run and waits a short while for it. A saved agent runs by name with its input. Anything else is a task in your words. With `repo` and `pr` it works on an open pull request. |
| `run_status` | Reads a run |
| `run_answer` | Sends your approve, correct or reject to a waiting run |
| `run_cancel` | Stops a run |
| `run_outcome` | Records whether a finished run was right or wrong |
| `runs_list` | Lists recent runs |
| `agents_list`, `agent_get`, `agent_save` | Lists saved agents with their figures, reads one, saves a definition |
| `tools_list` | Lists the tools connected on the project |
| `schedules_list`, `schedule_add`, `schedule_update`, `schedule_remove` | Manages schedules |

A long run outlives one chat reply. `run_start` returns after about 50 seconds with the run's status and address, and the assistant can check it again with `run_status`.

## What stays out of chat

Secrets do not go through chat. Connect a tool or a repository with the `sensei` command or on the dashboard, and never paste a token to a model.

Decisions stay with you. The server instructs the assistant to show you a waiting run's action and reason and to ask for your answer. It is told not to answer for you. When a run finishes, the assistant is told to show the output, the evidence and what the run was not sure about as they are.
